# 04. 수업 시간표 UX 과제 (재디자인의 핵심)

## 문제 정의

현재 사이트의 시간표는 **월~일 7일 격자**를 전제로 디자인되어 있지만, 실제 수업 운영은 다음과 같은 **비대칭 패턴**을 따릅니다:

```
평상시:    [ 월  화  수  목  금 ]  [ 토 ★ 일 ★ ]
            (수업 없음)              (주 수업)

대회 시즌:  [ 월 ●  화  수 ●  목 ●  금 ]  [ 토 ★ 일 ★ ]
            (특강/대비반)              (평소대로)
```

따라서 **"7일 모두 동등하게 보여주는 격자"**는 ❌
- 평일 칸이 늘 비어있어 **공백 과다**
- 주말이 **상대적으로 작게** 보여 중요도 전달 실패
- 대회 시즌 평일을 **예외적으로 표시**할 UI 패턴이 없음

## 사용자가 알고 싶은 것

학부모/학생이 시간표를 볼 때 가장 궁금한 것:

1. **"우리 아이 레벨 수업이 이번 주말 몇 시?"** — 레벨 + 날짜 + 시간
2. **"다음 회차는 언제?"** — 회차 정보 (예: 15회차, 16회차)
3. **"물리대회 전인데 특강 있나?"** — 평일 특강 유무
4. **"보강은?"** — 변동/보강 공지

## 요구사항 (지금까지 확인된)

- [x] **주말 수업이 메인**으로 보여야 함
- [x] 각 수업의 **회차** 표시
- [x] **물리대회 시즌엔 평일도 노출**
- [ ] 레벨별 색상/뱃지 구분 (A/B/C/D/E/물리대회대비반)
- [ ] 보강 수업 표시 방식 — **미결정**
- [ ] 월 전체 뷰 vs 주간 뷰 — **미결정**
- [ ] 공휴일/방학 처리 — **미결정**

## 기존 자산 (참고)

프로젝트 외부 폴더 `academy-weekend-calendar/`에 **아임웹용 주말 캘린더**가 이미 있습니다 (`imweb-embed.html`). 특징:
- 주말(토·일)만 크게 표시
- 평일은 **얇은 회색 스트립**으로만 표현
- 레벨별 색상 뱃지
- **Google Calendar API**로 일정 자동 반영
- 수업 클릭 시 모달

→ 이 접근은 **훌륭한 출발점**. 신규 사이트에서는 **같은 UX 원칙**을 유지하면서 **데이터 소스/배포 모델만 Next.js에 맞게** 재구성하면 됩니다.

## 디자인 방향 (브레인스토밍)

### 접근 A: "주말 중심 + 평일 스트립" (현재 아임웹 임베드 방식)

```
┌──────────────────────────────────┐
│ 월 · 화 · 수 · 목 · 금          │ ← 얇은 회색 (수업 없을 땐 접힘)
├──────────────────────────────────┤
│                                  │
│    [토요일 - 11월 2일]           │
│    09:00 [A반] 15회차            │
│    11:00 [B반] 15회차            │
│    14:00 [C반] 15회차            │
│    ...                           │
│                                  │
│    [일요일 - 11월 3일]           │
│    ...                           │
│                                  │
└──────────────────────────────────┘
```

**장점**
- 사용자 멘탈 모델과 100% 일치 ("주말이 메인")
- 모바일에서도 세로 리스트로 자연스럽게 전환
- 대회 시즌엔 평일 스트립이 **"펼쳐지면서"** 수업 노출

**단점**
- 월 전체 흐름을 한눈에 못 봄 → 보조 뷰 필요

### 접근 B: "월 캘린더 (평일 축소)"

```
┌─────────────────────────────┐
│  11월 2026                  │
├─┬─┬─┬─┬─┬───┬────┤
│월│화│수│목│금│ 토│  일│
├─┼─┼─┼─┼─┼───┼────┤
│ │ │ │ │ │  1│   2│
│ │ │ │ │ │★★★│ ★★★│
├─┼─┼─┼─┼─┼───┼────┤
```

평일은 좁은 칸, 주말은 **2~3배 넓은 칸**.

**장점**
- 월 전체 흐름 조망
- 익숙한 캘린더 레이아웃

**단점**
- 모바일에서 **구조가 깨짐** (주말만 넓어진 격자가 반응형 어려움)
- 평일 수업 많아지는 대회 시즌에 레이아웃이 **고무줄처럼** 변함

### 접근 C: "주간 포커스 + 월 미니맵"

```
┌─────────────────────────────────────┐
│ 이번 주 수업                        │ ← 메인 (큰 리스트)
│  토 11/2 · 일 11/3                  │
│  수업 상세들...                     │
├─────────────────────────────────────┤
│ [11월] ○○●○○●●○○●●                │ ← 월 미니맵 (수업 있는 날 점)
│                                      │
│ [< 지난주]            [다음주 >]    │
└─────────────────────────────────────┘
```

**장점**
- "이번 주 뭐 있지?" 질문에 즉답
- 월 미니맵으로 전체 흐름도 확인 가능
- 모바일 친화적 (세로 쌓임)

**단점**
- 네비게이션(주 이동) UI를 추가해야 함

### 추천: **접근 A를 베이스로 + C의 월 미니맵 요소 결합**

이유:
1. 기존 임베드가 이미 A 방향이고 사용자가 익숙함
2. 모바일 반응형이 가장 쉬움
3. 월 미니맵을 상단에 추가하면 월 흐름도 커버
4. 대회 시즌 평일 노출은 **"평일 스트립을 펼침 상태로"** 전환하는 걸로 처리

## 회차 표시 방식 (초안)

```
┌─────────────────────────────────┐
│ [A반] 09:00 ~ 10:30             │
│ 15회차 · 역학 운동량             │
│ 강사: 조한수                     │
└─────────────────────────────────┘
```

- **레벨 뱃지** (색상 + 레벨명)
- **시간**
- **회차 번호 + 수업 주제** (한 줄)
- **강사명**

### 회차 데이터 모델 (제안)

```typescript
type ClassSession = {
  id: string;
  level: 'A' | 'B' | 'C' | 'D' | 'E' | '물리대회대비반';
  sessionNumber: number;        // 15회차
  topic?: string;                // "역학 운동량"
  startAt: string;               // ISO datetime
  endAt: string;
  teacherId: string;
  type: 'regular' | 'competition-prep' | 'makeup';
  // regular: 정규(주말)
  // competition-prep: 물리대회 대비 평일 특강
  // makeup: 보강
};
```

## 데이터 소스 결정 (중요)

누가/어떻게 시간표를 입력하는가?

### 옵션 1: Google Calendar (기존 방식 유지)

- 학원 담당자가 **Google 캘린더에 수업 등록**
- 사이트가 Calendar API로 **실시간 조회**
- 제목 포맷: `[A] 15회차 역학 운동량` 처럼 **대괄호 레벨 + 회차**

**장점**: 입력 UX가 이미 익숙, 모바일 캘린더 앱으로도 수정 가능
**단점**: API Key 노출 리스크, 캘린더 제목 포맷을 **엄격히 지켜야** 파싱 가능

### 옵션 2: Headless CMS (예: Sanity, Contentful)

- 전용 어드민에서 수업 등록
- 수업 타입/회차/강사 등 **구조화된 필드**

**장점**: 데이터 품질 안정, 반복 수업 템플릿 등 고급 기능
**단점**: 학원 담당자 **학습 비용**, 월 사용료

### 옵션 3: 레포 내 JSON/MDX

- 레포에 `data/schedule.json` 같은 파일로 관리
- 수정 시 커밋 → 자동 배포

**장점**: 완전 무료, Git 히스토리 = 변경 이력
**단점**: 학원 담당자가 **Git을 다룰 줄 알아야** 함 → 비현실적

### 추천: **옵션 1 (Google Calendar)**

- 기존 임베드가 이 방식으로 돌아가고 있음 → **운영 노하우 축적됨**
- Next.js에선 **서버 사이드에서 API 호출 + 캐싱**으로 API Key 안전 보호 가능
- 캘린더 제목 파싱 규약을 유지
